# LightLink

ارسال متن بین دو گوشی با نور فلش/دوربین یا صدا (بدون اینترنت، بلوتوث و وای‌فای) و فاصله‌سنج رعدوبرق.

**وضعیت: مرحله ۲ (کانال نور).** ارسال با فلش و دریافت با دوربین پیاده‌سازی شده و منطق آن با شبیه‌سازی کانال روی JVM آزموده شده است، ولی هنوز روی دو گوشی واقعی سنجیده نشده است. صدا و فاصله‌سنج در مراحل بعد می‌آیند.

## ساخت APK با GitHub (بدون Android Studio)

1. در GitHub یک مخزن جدید بسازید (مثلاً `LightLink`).
2. محتوای این پوشه را در مخزن قرار دهید (`Add file ← Upload files` یا `git push`).
3. به تب **Actions** بروید؛ workflow با نام **CI** روی هر push اجرا می‌شود.
4. پس از سبز شدن، از بخش **Artifacts** فایل `lightlink-debug-apk` را دانلود و از حالت فشرده خارج کنید.
5. APK را روی **هر دو گوشی** نصب کنید (فعال‌سازی «نصب از منابع ناشناس»).

اگر CI قرمز شد، متن خطا (خطوط `e:` یا `FAILED` یا بخش `What went wrong`) را برای توسعه‌دهنده بفرستید.

## آزمایش کانال نور

1. روی هر دو گوشی: صفحه‌ی اصلی ← «ارتباط نوری و صوتی».
2. گوشی گیرنده: زبانه‌ی «دریافت»، مجوز دوربین را بدهید، دوربین را روبه‌روی فلش فرستنده بگیرید (حدود ۲۰ سانتی‌متر)، کادر زرد را روی نور فلش بگذارید و «شروع دریافت» را بزنید.
3. گوشی فرستنده: زبانه‌ی «ارسال»، پیام کوتاه بنویسید و «شروع ارسال» را بزنید.
4. ارسال کند است (برای «سلام» حدود یک دقیقه). جزئیات و جدول زمان در `docs/LIGHT_CHANNEL.md` است و چک‌لیست تست در `docs/DEVICE_TEST_CHECKLIST.md`.

## ساختار

- `app/`: اپلیکیشن اندروید (Kotlin، Jetpack Compose، Material 3، راست‌به‌چپ، CameraX)
- `core-protocol/`: ماژول Kotlin خالص برای پروتکل (بسته، CRC16، Hamming، بازسازی پیام)
- `core-dsp/`: ماژول Kotlin خالص برای مدولاسیون و دمدولاسیون نور (Manchester) به‌همراه شبیه‌ساز کانال برای تست
- `docs/`: مشخصات پروتکل، کانال نور و چک‌لیست تست دستی
- `.github/workflows/ci.yml`: تست‌های واحد و ساخت APK دیباگ

## نکات فنی

- حداقل اندروید ۸ (API 26)، compileSdk/targetSdk برابر ۳۵، JDK 17، فقط حالت عمودی.
- مجوز `INTERNET` اعلام نشده است. مجوز دوربین فقط برای خواندن نور فلش است و تصویری ذخیره یا ارسال نمی‌شود.
- گزارش lint ساخته می‌شود ولی ساخت را متوقف نمی‌کند (`abortOnError = false`)؛ پیش از انتشار نهایی دوباره سخت‌گیرانه می‌شود.
- فونت Vazirmatn در مرحله‌ی ۵ (یکپارچه‌سازی UI) داخل پروژه قرار می‌گیرد.

## محدودیت‌های شناخته‌شده

- بدون تست روی گوشی واقعی؛ کد Android در محیط ساخت من کامپایل نشده و اولین اجرای CI نخستین تأیید آن است.
- کانال نور فقط برای پیام‌های بسیار کوتاه عملی است (چند ده ثانیه تا چند دقیقه).
- امضای انتشار (release signing) در مرحله‌ی ۶ اضافه می‌شود.
